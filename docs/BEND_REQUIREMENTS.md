# ОБЯЗАТЕЛЬНЫЕ требования: загибы и масштаб стола (Five-130TG)

**Статус:** обязательный документ для реализации и ревью.  
**Версия документа:** 0.001 (2026-07-16).  
**Область:** Telegram Mini App (`web/tg.html`, `web/js/engine.js`) и последующие порты UI.

Любая правка раскладки стола **должна** соответствовать этому файлу.  
Полные правила Linux TUI (`Five-130/docs/graphics_rules.txt`) — справочник; для TG v0.001 действуют **упрощения ниже**.

---

## 1. Цель

1. Камни **не** сжимаются «на всякий случай» при росте креста.
2. Уменьшение размера — только когда **хотя бы одно** направление (влево / вправо / вверх / вниз) занимает критическую долю доступного места.
3. Вертикальные ветки (up/down) при нехватке места делают **первый** загиб против часовой стрелки ↺ (как Linux §3.0): **up→налево**, **down→направо**.
4. В TG v0.001 **нет** загибов главной линии и **нет** повторных загибов (up→left→down и т.п.) — только первый ↺-загиб вертикальных веток.

---

## 2. Термины

| Термин | Значение |
|--------|----------|
| **Якорь** | Спиннер, если есть; иначе центр (первый камень). |
| **Направление** | Одно из четырёх: `mainLeft`, `mainRight`, `branchUp`, `branchDown`. |
| **Занятость направления** | Длина проекции камней этого направления от якоря / доступная длина от якоря до края поля стола (в той же оси). |
| **Предпочтительный размер камня** `cell_pref` | Размер «комфортной» клетки до вынужденного уменьшения. |
| **Порог уменьшения** `shrink_occupy` | Доля занятости, при превышении которой разрешено уменьшать `cell`. |
| **Порог загиба** `bend_occupy` | Доля занятости **вертикального** направления, при которой начинается первый загиб ↺ (up→влево / down→вправо). |

---

## 3. Масштаб камней (обязательно)

### 3.1. Запрещено

- Авто-fit всего bounding-box стола в viewport на каждом ходе так, что крест из 5–8 камней занимает <20% поля.
- Жёсткий множитель `scaleNormal=0.55` поверх fit, если ни одно направление не достигло `shrink_occupy`.

### 3.2. Алгоритм

1. Вычислить `cell_pref` из cfg (`board.cell.pref_px` / доля от min(W,H)).
2. Для якоря в центре поля стола посчитать занятость по 4 направлениям при `cell = cell_pref`.
3. Если `max(occupy) < shrink_occupy` → рисовать с `cell = cell_pref`.
4. Если `max(occupy) ≥ shrink_occupy` → уменьшить `cell`, чтобы максимальная занятость стала ≈ `shrink_target` (см. профили), но не ниже `board.cell.min_px`.

### 3.3. Стартовый камень (≤2 на столе)

`board.cell.scale.start` — **множитель ≥ 1** к `cell_pref` (по умолчанию **1.2**).

- Первый камень / дубль должен быть **не мельче** обычного `cell_pref`, на мобильном — чуть крупнее.
- **Запрещено** уменьшать старт формулой `scale.start / scale.normal` (legacy 0.275/0.55 ≈ ×0.5).
- При `scale.start < 1` в cfg (старые значения) клиент подставляет **1.2**.
- С 3-го камня используется обычный `cell_pref` (без стартового множителя); shrink — только по §3.2.

## 4. Загибы (обязательно для TG v0.001)

### 4.1. Область действия

| Направление | Загиб в v0.001 |
|-------------|----------------|
| `branchUp` | **Да** → первый ↺ **налево** (`graphics_rules` §4.3) |
| `branchDown` | **Да** → первый ↺ **направо** (`graphics_rules` §4.4) |
| `mainLeft` / `mainRight` | **Нет** |

Повторные загибы (up→left→down, down→right→up, …) в v0.001 **запрещены**.

### 4.2. Условие загиба

Первый загиб, когда `occupy(ветка) ≥ bend_occupy` (или хвост не влезает по высоте).

### 4.3. Геометрия и ориентация

**Ориентация дублей (обязательно, жёстко):** [TILE_ORIENTATION.md](TILE_ORIENTATION.md).  
На вертикальном участке веток **up и down** дубль всегда **горизонтальный**;
на главной и на гориз. хвосте загиба — **вертикальный**. Одна логика для обеих веток.

**Отложенный загиб на дубле (Linux `graphics_rules` §5.7 / §4.5) — обязательно:**  
если порог высоты достигнут **на дубле**, дубль **остаётся** на вертикальной оси
(горизонтально). Загиб (Turn) начинается на **следующем ординаре**, а не на дубле.
Иначе на узком viewport (`maxVert` мал) дубль уходит в хвост с `horiz=false` —
регрессия «дубль стоймя на Up/Down».

**Детальное правило L-стыка (обязательно):** [BEND_TURN_GEOMETRY.md](BEND_TURN_GEOMETRY.md).


1. На вертикальном участке: **дубль всегда горизонтальный**, ординар вертикальный ([TILE_ORIENTATION.md](TILE_ORIENTATION.md) §2).
2. После гориз. дубля на вертикали ординар продолжает **вниз/вверх по оси** без отрыва (§4.2), пока нет загиба.
3. **Turn — только L-стык** ([BEND_TURN_GEOMETRY.md](BEND_TURN_GEOMETRY.md)): торец Turn к **боковой** грани open-половины вертикального ординара; up→влево + flush **верх**; down→вправо + flush **низ**. **Запрещён** стык «T» на узком торце.
4. Если загиб сразу после гориз. дубля — следующий ординар идёт **сбоку на том же Y**, что и дубль.
5. На горизонтальном хвосте загиба: ординар горизонтально, дубль вертикально ([TILE_ORIENTATION.md](TILE_ORIENTATION.md) §2).
6. Только один боковой сегмент на ветку (без 2-го/3-го загиба).
7. **Не** начинать загиб на дубле вертикальной оси (§5.7) — см. выше.
### 4.4. Связь с масштабом

1. Загиб ↺ (если порог доститнут).
2. Уменьшение `cell` (если после загиба всё ещё тесно).

## 5. Предлагаемые параметры и комбинации (на выбор)

Все доли — от **доступного** места от якоря до края felt-поля (с учётом `board.margin`).

| ID | bend_occupy | shrink_occupy | shrink_target | cell_pref | Комментарий |
|----|-------------|---------------|---------------|-----------|-------------|
| **A** | 0.70 | 0.80 | 0.78 | min(44, 0.14·min(W,H)) | Ранний загиб, редкий shrink — **рекомендуется как старт тестов** |
| **B** | 0.75 | 0.80 | 0.75 | min(40, 0.12·min(W,H)) | Близко к формулировке «80%» |
| **C** | 0.80 | 0.85 | 0.80 | min(42, 0.13·min(W,H)) | Позже загиб, чуть позже shrink |
| **D** | 0.65 | 0.80 | 0.70 | min(48, 0.15·min(W,H)) | Агрессивный загиб, крупные камни |
| **E** | 0.80 | 0.80 | 0.80 | min(40, 0.12·min(W,H)) | Один порог на оба события |

### 5.1. Доп. параметры (общие)

| Ключ cfg | Смысл | Кандидаты |
|----------|--------|-----------|
| `board.cell.min_px` | Пол не даёт «пылинки» | 18 / 22 / 26 |
| `board.margin` | Доля поля под отступ | 0.04 / 0.06 / 0.08 |
| `board.bend.only_vertical_ccw` | TG v0.001 | всегда `1` |
| `board.bend.main_line` | Загибы main L/R | `0` в v0.001 |

### 5.2. Что выбрать для записи в cfg

Предложение к первому прогону: **профили A и B** параллельно (`board.layout_profile=A|B`), плюс общий `min_px=22`.

После вашего выбора — ключи попадут в `cfg/five130tg.cfg`.

## 7. Чеклист приёмки

- [ ] После 5–8 камней крест занимает заметную часть felt, а не «горошину» по центру.
- [ ] Shrink только при `max(occupy) ≥ shrink_occupy`.
- [ ] Ветка up загибается **налево**, down — **направо**; стык Turn = L, не T.
- [ ] Нет микро-камней вместо загиба при нехватке места по вертикали.
- [ ] Main left/right без загибов в v0.001.
- [ ] Профиль A/B/… читается из cfg.
