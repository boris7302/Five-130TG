## Цель (приоритет пользователя)

Игра **двух людей на двух устройствах**, каждый со **своего Telegram-аккаунта**:
приглашение, общая партия, поочерёдные ходы, уведомление соперника.

**Это не hot-seat** (два человека по очереди на одном телефоне).

Сейчас в Mini App: **Вы vs ПК** (режим AI) и **hot-seat** «два игрока на одном
устройстве» (этап 1, rev.#047) — последнее **не** заменяет кросс-девайс PvP.

| Сценарий | Без сервера | С relay (этап 2+) |
|----------|-------------|-------------------|
| Два аккаунта, два телефона | **Нет** — нет общего состояния | **Да** |
| Hot-seat на одном устройстве | Возможно локально (этап 1, dev) | Не цель |

---

## Почему без сервера два телефона не сыграют

Mini App **не синхронизирует** состояние между двумя клиентами.  
IndexedDB / CloudStorage — **персональные**; общей «комнаты» в Telegram API нет.

**Без relay-сервера** два разных `user.id` из `initData` на двух телефонах
**не могут** видеть один стол и передавать ходы в реальном времени.
Экспорт KV-файла — только async fallback, не live PvP.

Минимум для PvP:

| Компонент | Назначение |
|-----------|------------|
| **Match relay** | Хранит текст партии KV или diff ходов; выдаёт по `match_id` |
| **Авторизация** | `Telegram.WebApp.initData` → `user.id` (проверка на сервере) |
| **Приглашение** | Deep link `https://t.me/<bot>/app?startapp=<match_id>` |
| **Уведомления** | Bot API: «Ваш ход» / «Партия началась» |

## Этапы внутри 0.002

### Этап 1 — Hot-seat на одном устройстве (без сервера) — **ГОТОВО rev.#047, dev-only**

> **Не цель пользователя** (уточнение 2026-07-16 11:35). Hot-seat не заменяет PvP
> «два аккаунта — два телефона». Реализовано для отладки правил без сети.

- Режим `game_mode=ai|pvp` в сессии и cfg.
- Имена: в AI — slot 0 из `initDataUnsafe.user` (или «Вы»); в PvP — «Игрок 1» / «Игрок 2».
- UI: кнопка «Новая» → модалка «Против компьютера» / «Два игрока (одно устройство)».
- Движок: в PvP нет `runAiTurn()`; ходы по очереди на одном экране.
- Debug dump: `# mode=pvp`, `# player0_name=…`, `# player1_name=…`.

**Критерий:** два человека играют по очереди на одном устройстве (отладка правил).

**Онлайн PvP** (два телефона, два аккаунта) — **этап 2+**, приоритет пользователя.

### Этап 2 — Минимальный backend + invite — **приоритет пользователя**

- Сервис (или бот на Python/Node): `POST /match/create`, `GET /match/:id`, `POST /match/:id/move`.
- Тело = `Five130-MatchFormat/1` (тот же KV, что MatchStore).
- **Авторизация:** каждый клиент шлёт `Telegram.WebApp.initData`; сервер проверяет HMAC
  и привязывает `user.id` к `player0` / `player1`.
- Создатель получает `match_id` → `Telegram.WebApp.shareUrl()` или копирование ссылки.
- Второй игрок: `startapp=match_id` → Mini App подгружает партию с сервера.

**Критерий готовности:** два человека на **двух устройствах**, каждый со **своего
Telegram-аккаунта**, открывают одну партию и видят один стол.

### Этап 3 — Ходы и очередь

- После хода: `saveMatch` на сервер + polling или WebSocket «есть обновление».
- Блокировка: ход принимается только от `current` player_id.
- Таймаут хода (опционально, cfg).

### Этап 4 — Бот-уведомления

- При смене `current` → `sendMessage` сопернику с кнопкой «Открыть партию».
- По окончании раунда/матча — итог в чат (кратко).

**Критерий готовности:** не нужно вручную обновлять Mini App — приходит push в Telegram.

## Что не делаем в первом PvP

- Рейтинги, турниры, зрители
- Игра через экспорт файла как основной режим (только fallback)

- Полный Flutter-клиент
