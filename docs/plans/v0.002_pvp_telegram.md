# План v0.002 — PvP: два пользователя Telegram

**Статус:** план (линия 0.002)  
**Дата:** 2026-07-16  
**Связано:** [`v0.002_plan.md`](v0.002_plan.md), [`../MATCH_STORE.md`](../MATCH_STORE.md)

---

## Цель

Игра **человек против человека** внутри Telegram Mini App: приглашение, общая
партия, поочерёдные ходы, уведомление соперника.

Сейчас: только **Вы vs ПК** (`HUMAN=0`, `AI=1`, ход ПК в `engine.js`).

---

## Почему нужен сервер (или бот с хранилищем)

Mini App **не синхронизирует** состояние между двумя клиентами.  
IndexedDB / CloudStorage — **персональные**; общей «комнаты» в Telegram API нет.

Минимум для PvP:

| Компонент | Назначение |
|-----------|------------|
| **Match relay** | Хранит текст партии KV или diff ходов; выдаёт по `match_id` |
| **Авторизация** | `Telegram.WebApp.initData` → `user.id` (проверка на сервере) |
| **Приглашение** | Deep link `https://t.me/<bot>/app?startapp=<match_id>` |
| **Уведомления** | Bot API: «Ваш ход» / «Партия началась» |

## Этапы внутри 0.002 (предлагаемый порядок)

### Этап 1 — Подготовка клиента (без сервера)

- Режим `game_mode=ai|pvp` в сессии и cfg.
- Имена из `initDataUnsafe.user` (first_name / username) вместо фиксированного «Компьютер».
- UI: «Новая игра vs ПК» / «Игра с другом» (кнопка → позже invite).
- Движок: ход второго **человека** без `runAiTurn()`; валидация «не ваш ход».
- Расширение KV-заголовка:

```
# mode=pvp
# player0_id=123456789
# player0_name=Борис
# player1_id=987654321
# player1_name=Алексей
# current=0
```

**Критерий готовности:** локально можно играть «два human» на одном устройстве (отладка).

### Этап 2 — Минимальный backend + invite

- Сервис (или бот на Python/Node): `POST /match/create`, `GET /match/:id`, `POST /match/:id/move`.
- Тело = `Five130-MatchFormat/1` (тот же KV, что MatchStore).
- Создатель получает `match_id` → `Telegram.WebApp.shareUrl()` или копирование ссылки.
- Второй игрок: `startapp=match_id` → Mini App подгружает партию с сервера.

**Критерий готовности:** двое в разных чатах Telegram открывают одну партию и видят один стол.

### Этап 3 — Ходы и очередь

- После хода: `saveMatch` на сервер + polling или WebSocket «есть обновление».
- Блокировка: ход принимается только от `current` player_id.
- Таймаут хода (опционально, cfg).

### Этап 4 — Бот-уведомления

- При смене `current` → `sendMessage` сопернику с кнопкой «Открыть партию».
- По окончании раунда/матча — итог в чат (кратко).

**Критерий готовности:** не нужно вручную обновлять Mini App — приходит push в Telegram.

## MVP 0.002 (реалистичный объём)

В рамках **0.002** целимся минимум в **этапы 1–2** (+ начало 3):

| Deliverable | Выкладка |
|-------------|----------|
| Режим PvP в UI и движке (без AI на ходу 2) | rev.0.002.x |
| Простой relay-сервер (1 инстанс, SQLite или файл) | отдельный репо / `server/` |
| Invite по deep link + загрузка партии | rev.0.002.x |
| Polling обновлений каждые N с | rev.0.002.x |

**Этапы 3–4** (WebSocket, push-бот) — добить в 0.002, если успеваем; иначе перенос в **0.003**
без смены номера линии PvP (как подверсии rev).

---

## Что не делаем в первом PvP

- Рейтинги, турниры, зрители
- Игра через экспорт файла как основной режим (только fallback)
- JSON вместо KV
- Полный Flutter-клиент
